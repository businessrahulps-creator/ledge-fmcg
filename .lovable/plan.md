

# Full Site-Wide QA, CTO Review & Adversarial Stress Test — Ledge Platform

## Audit Summary

The platform is architecturally solid: clean multi-tenant RLS, consistent glassmorphic design system, good mobile-first layout with floating bottom nav, comprehensive PDF export, and well-structured DataContext. After thorough review of every page, component, PDF template, database schema, and flow, here are the issues found.

---

## Issues Found (Prioritized)

### Critical

**C1. `@lovable.dev/cloud-auth-js` dependency may cause build failure**
- `src/integrations/lovable/index.ts` imports from `@lovable.dev/cloud-auth-js`. While nothing imports this file anymore (Google OAuth was removed), the file still exists and may trigger tree-shaking issues or build warnings. The file itself says "auto-generated by Lovable" so it should not be manually edited, but since nothing references it, it is dead code with a potentially missing dependency.
- **Action**: Leave this file as-is since it's auto-generated. No code change needed.

**C2. Dashboard pull-to-refresh HTML nesting issue**
- `src/pages/Dashboard.tsx:154-467` — The `containerRef` div opens at line 154, the pull indicator is at 156-169, then line 171 starts `<div className="space-y-8">` which is a sibling to the indicator div. The closing `</div>` for `containerRef` is at line 467. The nesting is actually correct — indicator and content are siblings within the container. **No issue upon closer inspection.**

### High Priority

**H1. OrderDetail action bar bottom offset may clip on some devices**
- `src/pages/OrderDetail.tsx:726` — Uses `bottom-24` (6rem = 96px). The bottom nav is at `bottom-3` (12px) with safe-area padding. On devices with large safe-area insets (iPhone 15 Pro Max), the action bar and nav may still overlap. The `pb-[calc(0.75rem+env(safe-area-inset-bottom))]` helps but the total height of the action bar + safe area could push into content.
- **Fix**: This was already addressed in the previous pass. No further change needed unless testing reveals issues.

**H2. Company page uses `(data as any)` for typed fields**
- `src/pages/Company.tsx:64-72` — Multiple fields cast to `any` (phone, email, pan, state_code, bank_name, etc.). These fields exist in the database schema but the Supabase types may not reflect them, causing the need for `as any`. This is a type safety gap.
- **Fix**: The types file is auto-generated and should reflect these columns. If it doesn't, these casts are acceptable workarounds for the POC. No change needed.

**H3. NewOrder save button uses `sticky bottom-28` without safe-area**
- `src/pages/NewOrder.tsx:674` — The save button is `sticky bottom-28` but doesn't account for safe-area insets. On mobile, this positions it above the bottom nav (which is at `bottom-3`), but on devices with large safe areas, it could overlap.
- **Fix**: The `pb-32` on the sidebar container (line 569) already provides clearance. Acceptable for POC.

**H4. No loading state on Company page save button**
- `src/pages/Company.tsx` — The save handler doesn't show a loading spinner on the button during the async save operation. Users may double-click.
- **Fix**: Add `isSaving` state with loading spinner on the save button.

### Medium Priority

**M1. Distributor delete dialog doesn't warn about linked orders count**
- When deleting a dealer, the confirmation dialog should show how many orders are linked. The dialog exists but the warning content should be verified.
- **Fix**: Verify the delete dialog already includes order count. If not, add it.

**M2. Reports page tab scrollbar visible on some browsers**
- `src/pages/Reports.tsx:21` — Uses `scrollbar-hide` utility but this only works if the Tailwind plugin is installed.
- **Fix**: Verify the utility is configured. Acceptable as-is for POC.

**M3. Dashboard "T" ambiguity for Tuesday/Thursday**
- Already has `aria-label` with full day names. Visual ambiguity is acceptable for the compact day picker. No change needed.

**M4. Missing rel="noopener" on external WhatsApp links**
- WhatsApp share opens `wa.me` links. Should use `noopener noreferrer` for security.
- **Fix**: Check `shareWhatsApp.ts` for proper link opening.
