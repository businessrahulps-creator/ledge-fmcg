# Make every PDF look world class

All PDFs in the app — GST bills, credit notes, order confirmations, dealer and salesperson statements, the Command snapshot, the Performance report, and every report and money-desk export — are built from one shared set of layout rules. Those shared rules have real layout faults today, so fixing them once lifts every document at the same time.

## What is wrong now (confirmed by reading the layout code)

1. **Text runs into the footer on long documents.** The page reserves the same 40pt margin at the bottom as at the sides, but the "Generated by Ledge · page X of Y" strip is pinned inside that margin. Any table that flows past one page prints rows on top of the footer.
2. **Table headings vanish after page one.** No table repeats its heading row on later pages, so page two of a long bill or report is a wall of unlabelled numbers.
3. **The non-GST bill table is wider than the page.** Its columns add up to 103%, so the last money column is pushed off the right edge and clipped.
4. **Amounts lose their paise.** The shared money formatter rounds to whole rupees, yet the round-off line prints two decimals — a bill can show a grand total that does not match the figures above it. Tax documents must show paise.
5. **No rupee symbol.** Amounts read "Rs. 2,124" because the built-in font has no ₹ glyph.
6. **Headers squash.** The company block and the document title share a row with no width limits, so a long business name or a long title crushes the other side.
7. **Summary cards get thin.** Rows of summary cards never wrap, so six or more figures become unreadable slivers; the Command snapshot mixes wrapping and stretching and produces uneven card widths.
8. **Heavy background on every page.** The full bone-coloured page background prints as a solid ink block on office printers and looks dull on screen.

## What will change

**One shared foundation, applied everywhere**
- Give pages a proper bottom margin so nothing can ever touch the footer, and repeat the footer and page numbers on every page.
- Mark every table heading so it repeats at the top of each page, and keep a row from being orphaned alone at a page break.
- White page with the bone/midnight brand used as accents (heading band, section rules, totals block) — cleaner on screen, correct on paper.
- Consistent type scale, tighter column rhythm, and even spacing between sections so every document has the same measured feel.
- Embed a font that carries the ₹ symbol, so all amounts print with the real rupee sign.

**Money accuracy**
- Amounts print with paise on financial documents (bills, credit notes, statements, payment lists) and stay rounded on summary/analytics cards where whole rupees read better. Same figures as the screen, to the paisa.

**Per-document fixes**
- GST bill / credit note: correct the over-wide non-GST column set, align the line table, tidy the seller/buyer blocks, totals box and bank details, and make the signature and "amount in words" areas sit properly at the end.
- Order confirmation: keep the existing "not a tax invoice" wording, restyled to match.
- Dealer and salesperson statements: repeatable headings, aligned money columns, clear closing-balance block.
- Billing exports (collections, payments, documents, aging): fit the columns to the page, right-align money, keep the Reference and Status columns readable.
- Command snapshot and Performance report: even card grids, consistent section spacing, no half-empty pages.
- Reports (dealer, product, payment, dispatch, sales team): all driven by the shared report layout, so they inherit every fix.

**Verification**
Generate a sample of each document type from real seeded data — including a bill long enough to run to three pages and a dealer with a very long name — render the pages to images and inspect each one for overlap, clipping, cut-off text, misaligned columns and spacing before calling it done. Then run the typecheck, tests and build.

## Out of scope
No change to money formulas, GST calculation, how bills are raised, document numbering or any business rule. This is layout, typography and formatting only — the numbers printed stay exactly the numbers the app already holds.

## Technical notes
- Shared: `src/components/pdf/PdfStyles.ts`, `PdfHeader.tsx`, `PdfFooter.tsx`, `ReportPdf.tsx`, `src/utils/exportPdf.ts`.
- Documents: `GstInvoicePdf`, `OrderInvoicePdf`, `DealerStatementPdf`, `SalespersonStatementPdf`, `CommandPdf`, `PerformanceReportPdf`.
- Add `paddingBottom` clearance on `page`; `fixed` on every `tableHeader`; `wrap={false}` kept per row plus `minPresenceAhead` on tables.
- `formatCurrencyPdf` gains a precision option (2 for documents, 0 for KPI cards); register a ₹-capable TTF via `Font.register` bundled from `src/assets`, with a Helvetica fallback if registration fails.
- Non-GST column widths in `GstInvoicePdf` rebalanced to 100%.
- QA via a temporary render script + `pdftoppm` image inspection; then `npx tsgo --noEmit`, Vitest, build log.
